## 0. 阅读指南

### 0.1 一页结论

| 负责人要回答的问题 | 本稿给出的交互答案 | 在哪里看 |
|---|---|---|
| 当前是 Consult 还是 Review？ | 固定模式徽标 + 窗口标题 + 全工作区切换；Review 不嵌在 Consult 回复区里 | S01、公共外壳、§5 |
| 这次外发到哪里？ | 入口、发送前、进行中、结果、审查生成、审计抽屉都固定显示目的地；不静默切换，不显示 endpoint/密钥 | S01–S14、§5.1、§7.11 |
| 回答来自哪些来源？ | 回答旁显示来源摘要，默认折叠；来源抽屉列 ref/version/状态；无查询时明确“上下文来源详情未提供” | S04、S14、§8 |
| 下一步能做什么？ | 每个结果/决定状态都有明确主操作；进行中只显示等待和发送详情，不伪造取消 | §6、§7 |
| Consult 会不会产生候选？ | 不会。Consult 没有“保存为候选/提交 Belief”按钮；D7=B：Review 只通过固定工作区导航进入 | S02、S04、§2、D7 |
| 拒绝之后还能批准旧候选吗？ | 不能。拒绝后工作项“已暂停”，旧候选不可批准；重新考虑需要新许可、新审查轮次、新候选 | S11、S13、§6 |

本稿的三个关键结论：

1. **外壳固定五件事**：工作区导航、模式、目的地、会话身份、当前主操作。它们不随内容滚动，也不被窗口缩放挤出。
2. **Consult 与 Review 是两个工作区**，不是两个内容标签页；固定导航切换整页，Review 的批准/拒绝永远不出现在 Consult 的回复面板中。
3. **当前有真实接口缺口**：候选枚举、候选差异、候选来源详情，Consult 历史/恢复/进度，拒绝后重新许可的发放。线框画出目标交互，但明确标注 C12b/C12c 缺口，不伪装成已可执行。

### 0.2 术语

| 术语 | 本稿含义 |
|---|---|
| Consult | 日常咨询工作区：提问、生成回答、查看来源；不产生候选。 |
| Review | 独立认知审查工作区：查看工作项、审查候选、批准或拒绝。 |
| 候选（candidate） | 待审查的 Belief 变更提案，不是已提交的 Belief。 |
| Belief | 认知库中的信念条目；只有 Review 批准并拿到回执后才算提交。 |
| WAIT | 审查后选择“暂不形成 Belief”的正式结果，带回执，不是失败。 |
| 目的地（destination） | 本次模型调用实际使用的本地或外部 provider/model；由可信宿主配置提供。 |
| 来源（source） | 已获准披露的输入、记录、事件、查询产物或回复产物引用。 |
| 脱敏/不可见（redacted） | 当前访问范围不允许显示回执内容；生命周期状态不变。 |
| 缺口（gap） | 没有正式公共接口支撑的数据或动作；本稿只画目标态或禁用态。 |

## 1. 设计目标、非目标、假设

### 1.1 目标

本稿要让负责人能在一分钟内判断“交互是否清楚”，具体标准是：

- **四问测试**（任一主屏，五秒内可答）：
  1. 现在是 Consult 还是 Review？
  2. 这次内容发到哪里？
  3. 回答/候选的依据来自哪些来源？
  4. 下一步的主操作是什么？
- **状态可区分**：`answered` / `waiting` / 材料或查询说明 / `failed` / `incomplete` / `stale` 在文案、图标、主操作上都能区分。
- **Review 后果可理解**：候选精确变化、Approve/Reject 的后果、提交回执、拒绝后“已暂停”。
- **没有死路**：每个状态都有明确的下一步；没有正式接口的动作宁可禁用并说明，不画成可点击。
- **隐私与权威边界可见**：目的地常驻；来源按需展开；内部字段不出现；刷新后不以本地缓存覆盖 Facade/Store 的权威结果。
- **Windows 桌面可用**：最小、默认、宽屏三种尺寸下主操作可达；支持系统 DPI/缩放、键盘和输入法。

### 1.2 非目标

本稿明确不做：

- 不写 UI、桌面程序、安装器、构建脚本或任何运行时代码。
- 不选择或评估桌面技术栈（不指定 Tauri、Electron、Qt 或其他方案）。
- 不启动 Web server，不要求浏览器，不复制旧 Workbench 的面板/仪表盘。
- 不做 C12b/C12c 实现、C13、真实模型实验、Persona/Memory/语义检索扩展、ACL/权限平台。
- 不新增 C11/C07 公共 API；不修改 C06–C11。
- 不把私人正文、数据库列、Prompt、HTTP body、原始 payload 写进设计稿或界面。
- 不 push。

### 1.3 假设与前置

- **载体**：独立 Windows 桌面应用。窗口可调整大小、最小化、最大化/还原；尊重系统 DPI 和文本缩放。
- **可信宿主**：`namespace`、`host_instance`、`operator`、权限、隐私范围、用途和目的地由可信宿主提供。桌面端只调用正式 Facade。
- **目的地**：宿主提供“本地/外部 + provider 标签 + model 标签”的描述；没有该描述时发送被禁用。模型输出不能决定目的地。
- **接口现状**：C11 `ConsultFacade` 是同步调用，没有进度事件或取消接口；C07 `ReviewFacade` 没有候选枚举/差异接口；C05c `read_experience` 只提供部分候选/产物读取。缺口见 §9。
- **语言**：界面主语言为中文；`Consult`、`Review` 作为模式名保留英文，避免翻译后混淆。
- **示例**：本稿所有问题、回答、候选、来源均为合成占位，明确标注“示例”。
- **线框外壳**：D1=A 已决定：单窗口 + 固定工作区导航；S01–S14 按此绘制。切换工作区是整页替换，不是内容标签页。
- **静态交付**：本稿是 Markdown/ASCII 线框；评审不需要启动任何服务，也不调用真实模型。

### 1.4 不可投票的技术安全项

以下由既有技术边界固定，D1–D7 不能修改：

1. 目的地必须始终可见；不能隐藏、静默切换或用模型输出决定。
2. Review 必须是独立工作区；不能从 Consult 的回答面板直接批准/拒绝。
3. Consult 不能创建、保存或提交候选；不能弹出“保存为 Belief”阻断对话框。
4. 拒绝是候选的终态；旧候选不能复活，重新考虑必须走新许可、新审查轮次、新候选。
5. 不显示 `state_revision`、内部 omissions、完整 `QueryResult`、`to_artifact_body`、Prompt、HTTP body、数据库内部字段。
6. 材料/查询说明只是展示提示，不是新状态；只能依据已披露的 `material_status`（complete/partial）与 `status`（ok/empty/unavailable）组合，不推断隐藏内容是否存在/多少；`material_status=partial` 不代表必然存在隐藏记录。
7. 权威结果来自 Facade/Store；刷新、重载、断线后不得用本地缓存覆盖。
8. 薄客户端：只调用正式 Facade，不在 UI 重实现检索、候选生成、提交状态机或认知逻辑。
9. 不复制旧 Workbench；新应用是薄交互层，不做大量仪表盘。
10. 不 push；不修改 C06–C11。

### 1.5 已确认的产品方向

- C12 最终采用**独立 Windows 桌面应用**，不以终端或浏览器作为主要图形交互入口。
- **P0 目标**：可靠、可操作的最小 Windows 桌面客户端；Consult 是日常主工作区，Review 是显式分离的审查工作区。
- **长期方向**：更自然的连续对话，以及经过正式权限与来源管理的会话历史、恢复和持续经验能力；不在 C12a 的实现范围内。
- C11 的一次性 Consult 闭环不应被误认为最终对话形态；本稿只把一次 Consult 作为 P0 的最小闭环。
- 技术栈、打包、部署、C12b/C12c 实施拆分不在本稿决定范围；C12a 不授权开始 C12b/C12c 编码。

### 2.2 Consult（日常主界面）

1. **S01 入口**：确认 namespace/host/operator；显示 `Consult` 模式；目的地常驻；进入 Consult。
2. **S02 输入与发送前**：写问题或选已登记输入；显示输入摘要与来源范围；目的地常驻；发送。
3. **S03 处理中**：显示“处理中”和本次发送范围；目的地保持可见；不伪造生成/查询子阶段（C11 无进度事件）。
4. **S04 answered**：回复正文；来源摘要默认折叠；可复制/新提问；完成区不提供 Review 入口（D7=B）。
5. **S05 waiting**：明确“等待（暂无完成回答）”，不是错误；有 `reply` 时只作为等待说明，不伪造回答。
6. **S06 材料/查询说明**：`material_status=partial` 显示“可能不完整”；`status=empty` 显示“没有可披露结果”；`status=unavailable` 显示“查询结果不可用”；都不是新状态。
7. **S07 failed/incomplete/stale**：三种原因标签与下一步；不显示半成品或原始输出。
8. **结束**：不强迫保存；没有“保存为候选/提交 Belief”；Review 只通过固定工作区导航进入。

### 2.3 Review（独立认知审查工作区）

1. **S08 工作列表**：来自正式 `managed_work`/`legacy_work`；受管项与旧项分开展示；标注差异。
2. **S09 候选差异**：目标态展示当前 vs 候选的 claim/claim_type/scope/来源/strength/status 和差异摘要；**当前无正式候选正文/差异接口，标 C12c 缺口**。
3. **S10 批准与回执**：Approve 二次确认；提交回执；WAIT 回执变体。
4. **S11 拒绝与暂停**：Reject 二次确认；“已暂停”；批准不可用。
5. **S12 异常**：stale/denied/failed/incomplete；权限不足单独区分。
6. **S13 重新授权复查**：旧候选不可复活；新许可 → 新审查轮次 → 新候选；许可发放无公共接口，标 C12c 缺口。
7. **S14 来源/审计**：ref/version/model adapter/attempt；不显示内部字段。

## 4. 14 项场景线框与注释

### 4.0 共用 Windows 窗口外壳

所有屏共用四个区。模式、目的地、会话身份和主操作不随正文滚动：

```
┌─ QUINTESSENCE · Consult ───────────────────────────────────  —  □  ×
│ 工作区  [Consult]  [Review]          目的地：外部 · 合成提供方 / 合成模型 A
│ 当前：[Consult] 日常咨询
│ 命名空间 demo-ns · 宿主 lab-01 · 操作者 owner
├────────────────────────────────────────────────────────────────────
│
│  主内容区（唯一可滚动区；默认最大宽度 760）
│
├────────────────────────────────────────────────────────────────────
│ [主操作]   [次操作]          来源：输入 1 · 查询 3      [来源与详情]
└────────────────────────────────────────────────────────────────────
```

规则：

- **标题栏**使用系统窗口边框和系统按钮；应用内再放一行模式徽标，避免标题被截断后看不出模式。
- **工作区导航**固定在状态区：`Consult | Review`；点击后整页替换工作区，不是内容标签页，也不把 Review 按钮嵌进 Consult 回复区。
- **状态区**固定显示：工作区导航、模式徽标、当前目的地、namespace/host/operator 摘要。最小窗口可分成多行，仍全部可见。
- **动作区**固定在底部；主操作不得被正文挤出可视区。正文滚动时动作区不动。
- **来源抽屉**是覆盖层，不挤压答案主区；关闭后焦点回到打开它的按钮。
- 最小窗口下动作区可换行，但主操作必须仍在首行；没有横向滚动。
- 所有屏的“绝不显示”字段相同，见 §8.3；单屏注释只列该屏额外风险。
- 为保持线框可读，后续只示例 S01/S04/S06/S08 的工作区导航；实际实现中所有屏的状态区都保留该导航。

- 显示：按 `status` + `material_status` 的合法组合显示对应说明；`truncated` 只在来源抽屉说明。

- 接口：`ConsultResult.query_body` 的公开投影。
- 薄客户端：只读取 `material_status`（`complete`/`partial`）、`status`（`ok`/`empty`/`unavailable`）、`truncated` 并格式化；不重新执行查询，不推断 omitted 内容。
- 说明：**材料/查询说明不是新状态**；`ConsultResult.state` 仍是 `answered`。

组合规则：

| `status` | `material_status` | 界面说明 |
|---|---|---|
| `ok` | `complete` | 无说明 |
| `ok` | `partial` | 材料说明：当前可披露材料可能不完整；本次回答仅基于可披露内容。 |
| `empty` | `complete` | 查询说明：本次查询没有可披露的结果。 |
| `empty` | `partial` | 查询说明：本次查询没有可披露的结果；当前可披露范围可能不完整。 |
| `unavailable` | `complete` / `partial` | 查询说明：本次查询结果不可用。 |
| 缺失/未知 | 任意 | 不显示材料结论；只在技术详情标注“状态不可用” |

边界：

- `material_status=partial` 只表示访问类别未覆盖完整策略集合，**不能解释为必然存在隐藏记录**。
- `material_status=complete` 也不保证没有 omission、删除或不可用条目；不写“材料完整”。
- `status=empty` 不是材料不足；`status=unavailable` 不是权限不足。
- `truncated=true` 只在来源抽屉显示“查询结果已截断”，不放进主回答。
- 本校正只改设计文档与 UI 映射；不新增 PCS 状态、错误码或公共 API。

- 权限：缺少 `review.generate` → `开始新的审查` 禁用；许可发放不在本应用权限模型内，`申请新的复查许可` 始终禁用直至 C12c 提供正式入口。

**数据与接口**

- 显示：`blocked=true`、`rerun_authorization_ref` 是否存在（只显示“已登记/未登记”）、旧候选引用/拒绝状态。
- 绝不显示：许可令牌、grant 引用值、内部 generation 数字、旧候选正文（当前无只读投影）。
- 接口：`managed_work` 的 `blocked`/`rerun_authorization_ref`；`review()` 生成新候选。
- 缺口：**没有正式公共接口发放 rerun grant 或绑定新的复查许可**（C12c）。本屏只能显示状态并调用 `review()`，不能自己“授权”；许可发放必须在宿主管理流程完成。

### 5.5 缩放、DPI 与 Windows 细节

- **系统 DPI**：跟随 Windows 100%/125%/150%/200%；布局按逻辑像素断点，不按物理像素写死。
- **文本缩放**：支持系统“放大文本”；不用固定高度裁切正文，按钮随文字增高；长中文标签换行而不是省略。
- **高对比度**：模式/目的地/状态不能只靠颜色；使用文字 + 形状/图标。窗口边框和焦点环使用系统颜色。
- **键盘**：`Ctrl+Enter` 发送/开始审查；`Esc` 关闭抽屉或取消对话框；Tab 顺序从状态区 → 主内容 → 动作区；焦点可见。
- **输入法**：中文 IME 组词期间按 Enter 只确认候选词，不发送；发送只由 `Ctrl+Enter` 或按钮触发。
- **剪贴板**：复制回答为纯文本；复制引用/回执为短文本；不把隐藏字段复制进去。
- **屏幕阅读器**：模式、目的地、状态、主操作有可读名称；抽屉/对话框有焦点陷阱和关闭标签。
- **减少动态**：跟随系统“减少动画”；进行中指示可以是静态文本 + 轻量进度，不依赖动画表达状态。
- **多显示器/任务栏**：窗口可最小化/最大化/还原；标题栏包含 `QUINTESSENCE — Consult/Review`，任务栏可区分模式。

### 5.6 D1=A：单窗口 + 固定工作区导航（布局层面）

D1 已决定为 **A 单窗口工作区切换**：

- **A 已采用**：从 S01 或状态区固定导航进入一个工作区；切换工作区是整页替换，不是标签页/侧栏。Review 不显示 Consult 的回答面板。
- **B 未采用**：Consult/Review 独立顶层窗口不再作为本期布局；如果未来重新评估，必须另立决策，不改变 Review 独立性。

所有工作区都遵守：

- 模式徽标、工作区导航、目的地、会话身份固定可见；
- Review 的批准/拒绝只出现在 Review 工作区；
- 切换工作区不保留“看起来已完成”的本地状态；权威状态从 Facade 重读；
- 一个工作区的缓存不能当作另一个工作区的权威结果。

## 6. Consult / Review 状态矩阵

### 6.1 Consult 状态

`ConsultResult.state` 只有 `answered` / `waiting` / `failed` / `incomplete` / `stale`；**没有 `insufficient` 状态**。材料说明只是 `answered` 上的展示提示。

| 状态 | 类型/条件 | 文案/状态 | 主操作 | 次操作/可用 | 禁止/不可用 | 下一步 |
|---|---|---|---|---|---|---|
| 就绪 | UI 状态；尚未发送 | “新的咨询” | 发送 | 添加/移除输入、查看发送范围、目的地说明 | 保存为候选；提交 Belief | 发送 → 处理中 |
| 处理中 | UI 状态；`interact` 在途 | “正在处理你的咨询…” | 无（等待） | 查看发送详情、最小化 | 取消、自动重试、切换目的地 | 等待 → 结果 |
| answered | `ConsultResult.state=answered` | “已回答” + 回复正文 | 复制回答 | 展开来源、新提问、目的地说明 | 保存为候选、提交 Belief、批准/拒绝 | 结束或新提问 |
| answered + 材料/查询说明 | `answered` 且 `material_status=partial`，或 `status` 为 `empty`/`unavailable` | 回答 + 对应说明（可能不完整/查询无结果/查询不可用） | 复制回答 | 查看来源范围、展开来源 | 查看隐藏数量/原因；推断存在性；把 empty 说成材料不足 | 结束或新提问 |
| waiting | `state=waiting` | “等待（暂无完成回答）”；有 `reply` 时显示“等待说明”，不当作回答 | 新提问 | 关闭、查看详情 | 复制回答、伪造回答、自动重试 | 新提问 |
| failed | `state=failed` | “未完成（failed）”；原因标签 | 新提问 | 查看技术详情、目的地说明 | 半成品当回答、自动重试、复制旧结果 | 新提问 |
| incomplete | `state=incomplete`；非终态 | “未完成（incomplete）”；没有可展示回答 | 新提问 | 查看技术详情 | 当成已回答/已结束；显示“继续”（无接口） | 新提问（无续跑） |
| stale | `state=stale` | “已过期（stale）”；上下文已变化 | 新提问 | 查看技术详情 | 使用旧结果、复制旧正文 | 新提问 |
| 权限不足 | UI/异常；`AuthorizationRequired`/`ScopeViolation` | “权限不足” | 返回入口 | 查看所需权限 | 显示任何正文、权限表、其他 namespace 数据 | 返回/联系宿主 |
| 恢复失败 | UI；重载/断线 | “本次咨询无法恢复” | 返回入口 / 新提问 | 查看说明 | 显示本地缓存正文、假装仍在途 | 新提问；C12c 需恢复接口 |

**关键规则**

- `waiting` 不是失败；`failed` 不是等待；`incomplete` 不是“已拒绝”或“已提交”。
- `incomplete` 非终态，但 C11 没有续跑接口；本稿不画“继续”。
- 材料/查询说明只引用 `query_body.material_status`（complete/partial）、`status`（ok/empty/unavailable）、`truncated` 公开字段，不引用内部计数；`partial` 不等于“必然有隐藏记录”。
- 重载后不展示本地缓存正文；Consult 当前无 `result()` 恢复接口，因此显示“无法恢复”，而不是回放旧回答。

### 6.2 Review 状态

| 状态 | 类型/条件 | 文案/状态 | 主操作 | 次操作/可用 | 禁止/不可用 | 下一步 |
|---|---|---|---|---|---|---|
| structural_only | `preview()` 结果；无持久化 | 不出现在用户界面；仅宿主预检 | — | — | 当成已提交/已保存 | 无 UI |
| pending | `ReviewView.state=pending`；候选行存在，无回执 | “待决定” + 候选差异（目标态） | 批准… | 拒绝…、来源详情、返回 | 自动提交、跳过审查、直接修改候选 | 批准/拒绝 |
| pending + 差异缺口 | 当前无候选正文/差异接口 | “候选内容暂不可查看” | 无（批准禁用） | 返回、查看状态 | 盲批、用 read_experience 现算 diff | 等待 C12c；不作决定 |
| committed | 回执存在 | “已提交（committed）” | 查看回执 | 返回列表、目的地说明 | 再次批准、把模型文本当回执 | 结束 |
| committed + redacted | 回执被当前访问范围隐藏 | “已提交（回执不可见）” | 返回列表 | 查看状态 | 把隐藏当失败/降级为 pending；伪造回执 | 结束 |
| waiting | WAIT 回执存在；工作项完成 | “已记录：暂不形成 Belief（WAIT）” | 查看回执 | 返回列表 | 当失败、再次批准、当异步等待 | 结束 |
| rejected | 候选被拒绝；工作项暂停 | “已拒绝 · 已暂停” | 重新授权复查 | 返回列表、查看历史引用 | 批准旧候选、撤销拒绝、复活旧候选 | S13 新许可/新审查 |
| stale | 工作/候选/Context 移动 | “已过期（stale）”；未提交 | 刷新工作列表 | 重新审查（若工作仍待处理）、查看详情 | 沿用旧候选、显示旧回执 | 刷新/新审查 |
| denied | 持久化审查入口拒绝 | “审查未启动（denied）”；未生成候选 | 返回工作列表 | 查看原因 | 当权限不足；绕过 gate；自动重试 | 返回/等待宿主 |
| failed | 生成/提交失败 | “审查未完成（failed）”；未提交 | 重新审查（新候选） | 查看技术详情、返回 | 伪造回执、原始输出、自动重试 | 新审查/返回 |
| incomplete | 无权威结论 | “结论不完整（incomplete）” | 刷新结果 | 返回工作列表、查看详情 | 推断为拒绝/提交；再次批准 | 恢复/返回 |
| 权限不足 | UI/异常；`AuthorizationRequired` | “权限不足”；未读取/提交 | 返回 | 查看所需权限 | 显示数据、权限表、token | 返回/联系宿主 |
| 恢复失败 | UI；重载/断线 | “无法恢复当前审查” | 返回工作列表 | 刷新 | 显示本地缓存候选、乐观回执 | 重新读取列表；C12c 候选枚举缺口 |

**关键规则**

- `committed` 只能由回执证明；模型说“已记住”不算。
- `waiting` 是 WAIT 回执，不是“等待模型”；文案必须写“已记录”。
- 拒绝是终态；`resolve(approve)` 对已拒绝候选返回 `rejected`，不复活。
- `denied`（审查 gate）与“权限不足”（Facade 权限异常）是两件事，文案和图标必须不同。
- `redacted=true` 不改变生命周期状态：`committed` 仍是 `committed`。
- 刷新/重载后以 `ReviewView`/`result()` 为准；不显示本地乐观状态。
- **C12c 前实际界面**：S09 只显示“候选内容暂不可查看”的缺口卡，批准/拒绝禁用；S10/S11 的批准/拒绝确认是目标态，当前不可达。候选枚举/来源详情不得从私有数据库或原始 payload 拼装。

### 6.3 状态转换（简图）

```
Consult:
  idle --发送--> processing --answered--> answered
                         |--waiting----> waiting
                         |--failed-----> failed
                         |--incomplete-> incomplete（非终态；无续跑 UI）
                         `--stale------> stale

Review:
  work --review--> { pending | waiting | denied | failed | stale | incomplete }
  pending --approve--> committed
  pending --reject----> rejected --新许可/新审查--> 新 pending

  任何状态 --权限不足--> 权限不足（UI，不改变已存在的生命周期状态）
```

## 7. 文案卡

### 7.1 语气规则

- 中文为主；`Consult` / `Review` / `WAIT` 保留英文模式/协议名，首次出现可加中文解释。
- 人称统一用“你”；不用“您”，不用感叹号，不卖萌，不训斥。
- 只描述“已发生什么 + 下一步”；不解释内部实现，不把技术码放在主文案。
- 不写“模型认为/模型记住了/模型决定提交”；只写“已记录/已提交/未完成”。
- `waiting` 不写成错误；`committed` 只在有回执时写；`rejected` 不写成“撤销”。
- 材料说明只写“可能不完整”，不写“有 N 条被隐藏”“因为权限不够所以看不到 X”。
- 不用“保存候选”“提交 Belief”出现在 Consult；Review 用“批准并提交”。
- 技术码只放在折叠的“技术详情”里，且只显示 `phase:code` 标签，不显示原始异常/HTTP body/Prompt。

### 7.5 WAIT

**Consult waiting**

```
标题：等待（暂无完成回答）
正文：模型这次没有给出完成的回答。这是一次有效结果，不是错误。
      如果模型给出等待说明，会单独显示在“等待说明”里，不作为回答。
      本次没有创建候选。
主操作：新提问
次操作：关闭 / 查看详情
禁止：自动重试；把等待显示为失败；把等待说明当作回答。
```

**Review waiting（WAIT 回执）**

```
标题：已记录：暂不形成 Belief（WAIT）
正文：本次审查没有形成 Belief；已记录为 WAIT 回执，工作项已完成。
      它不是失败，也不能再次批准。
主操作：查看回执
次操作：返回工作列表
禁止：当失败；当成异步等待；再次批准。
```

### 7.6 材料 / 查询说明

| 条件（公开字段） | 文案 | 位置 |
|---|---|---|
| `status=ok` + `material_status=partial` | 材料说明：当前可披露材料可能不完整；本次回答仅基于可披露内容。 | 回答下方一行 |
| `status=empty` + `material_status=complete` | 查询说明：本次查询没有可披露的结果。 | 回答下方一行 |
| `status=empty` + `material_status=partial` | 查询说明：本次查询没有可披露的结果；当前可披露范围可能不完整。 | 回答下方一行 |
| `status=unavailable` | 查询说明：本次查询结果不可用。 | 回答下方一行 |
| `status=ok` + `material_status=complete` | 不显示说明（`truncated=true` 只在来源抽屉显示“查询结果已截断”） | — |

统一后缀（只在“展开详情”中）：`本说明只反映公开的材料状态，不代表存在或不存在任何隐藏内容。`

边界说明：

- `material_status` 合法值只有 `complete` / `partial`；`status` 合法值只有 `ok` / `empty` / `unavailable`。
- `material_status=partial` 只表示访问类别未覆盖完整策略集合，**不能解释为必然存在隐藏记录**。
- `material_status=complete` 也不保证没有 omission、删除或不可用条目；不写“材料完整”。
- `status=empty` 是查询无结果，不是材料不足；`status=unavailable` 不是权限不足。
- 若公开字段缺失或出现未知值：不推断材料结论，只在技术详情标注“状态不可用”。

禁止文案：

- “有 3 条记录因权限不足被隐藏。”
- “你的权限不够，所以回答不完整。”
- “升级权限即可看到全部。”
- “本次回答一定完整。”

### 7.7 错误 / 失败

| 失败类别 | 标题 | 正文 | 主操作 | 技术详情 |
|---|---|---|---|---|
| 模型/网络 | 未完成 | 模型调用没有完成。没有生成回答。 | 新提问 | `model:<code>` |
| 格式校验 | 未完成 | 回复格式未通过校验，本次没有采用。 | 新提问 | `format:<code>` |
| 查询 | 未完成 | 确定性查询没有完成，本次没有生成回答。 | 新提问 | `query:<code>` |
| 上下文/绑定 | 已过期 | 上下文已变化，本次结果未采用。 | 新提问 | `context:<code>` / `bind:<code>` |
| 本地存储 | 未完成 | 本地存储暂时不可用，本次没有完成。 | 新提问 | `storage:<code>` |
| 配置/能力 | 未完成 | 本地模型配置不完整，无法开始咨询。 | 联系宿主/新提问 | `capability:<code>` |
| 未预期 | 未完成 | 发生了未预期的问题，本次没有完成。 | 新提问 | `phase:type` |

错误展示规则：

- 主文案不显示异常类型、HTTP 状态、body、Prompt 或模型原始输出。
- “技术详情”默认折叠；只显示 `phase:code` 标签。
- 不自动重试；重试必须由用户发起新的 Consult。
- 错误不覆盖已经存在的权威结果；如果已有结果，只显示错误提示，不删除结果。

## 8. 来源 / 审计字段清单

### 8.1 原则

- 只使用 Facade/Store 已公开的 DTO 字段；不读取 SQLite 列、不解析私有 Prompt/HTTP。
- 只展示可审查的 `ref` / `version` / `model adapter` / `attempt`；不展示内部状态机字段。

### 8.2 可见字段

|---|---|---|---|---|

### 8.3 绝不显示

| 字段/内容 | 原因 |
|---|---|
| `state_revision`（任何位置，包括回执对象里的字段） | 内部快照元数据；可能成为隐藏数据的存在性侧信道 |
| 内部 omissions（`not_authorized`、`source_ref_not_authorized`、`source_ref_redacted`、`redacted`、`unavailable` 等；这里的 `unavailable` 是内部 omission 原因，不是 `material_status`）及计数 | 会暴露未授权/隐藏内容的存在或数量 |
| 完整 `QueryResult` / 原始 `query_body` JSON / `to_artifact_body` | 包含内部字段或机器投影，不是用户可审查界面 |
| Prompt / `rendered_input` / 模型原始输出 | 私人正文与内部提示；不属于 UI 数据 |
| HTTP 请求/响应 body、headers、endpoint URL | 可能含密钥、内部地址或原始内容 |
| 数据库列/行、SQL、表名 | 内部实现，不是交互对象 |
| `access_ref`、`policy_ref`、grant/authorization 引用、许可令牌 | 授权凭据/内部引用，不是用户信息 |
| `proposal_digest`、`command_digest`、`decision_id`、`request_hash` | 内部完整性/审计键；不帮助用户做选择 |
| `generations` / `query_count` 预算计数 | 内部预算，不是回答质量或用户信息 |
| 密钥、API key、私密 endpoint | 安全底线 |
| 其他 namespace 的数据、隐藏来源的存在性/数量 | 隐私与 scope 边界 |

### 9.2 C12b 接线（不是新公共 API）

C12b 需要在桌面宿主层落地：

- 构造 `HostAccess` / `ConsultHostAccess`（namespace、host、operator、权限、隐私范围、用途）。
- 提供稳定的目的地描述（本地/外部、provider 标签、model 标签）；不显示 endpoint/key；未接线时 S01/S02 禁用发送并显示“宿主能力未就绪”，不假装已有授权上下文。
- 输入登记与摘要（C05b 路径）；桌面端不直接写 store。
- 在结果展示前复核当前访问范围；权限变化时不显示缓存正文。
- 把 `interact`/`review` 放到不阻塞 UI 的宿主工作线程；把失败映射为可展示的结果状态。
- 会话导航记录：只保存 `interaction_id` 等非正文键，供 `ReviewFacade.result()` 恢复；不保存正文/状态作为权威。

### 9.3 C12c 接口缺口（必须先补，不能画成已可执行）

1. **候选枚举**：按工作项列出 pending/历史候选，支持“继续当前审查”。
2. **候选差异/正文/当前版本**：正式 diff 投影，包含 claim/claim_type/scope/sources/strength/status 与当前版本。
3. **候选来源详情**：与候选差异配套的正式来源投影；不要求 UI 调 `read_experience` 现算。
4. **Consult 完整来源/attempt**：`ConsultResult` 的公开投影或正式读取接口。
5. **Consult 历史/恢复**：已知 interaction 的 `result()` 等价接口；重载后不靠本地缓存。
6. **Consult 进度/取消**：若产品需要子阶段或取消；否则保持 indeterminate。
7. **重新许可发放/绑定**：S13 的“新许可”需要正式公共接口；当前只有 WorkControl 字段。
8. **Review pending context/model adapter 归一化**：让审计/回执视图在不同入口拿到同一组公开字段。
9. **目标态隔离**：C12c 完成前，S09 的批准/拒绝禁用，S10/S11 的确认框不可达；S13 的 `申请新的复查许可` 始终禁用。只保留布局目标态。

### 9.4 停止条件

若落实交互需要新增 C11/C07 公共 API 才能表达候选差异/枚举/来源，**停止并列入 C12c**，不设计假数据接口；若需要选择桌面技术栈、打包/部署，停止；若必须启动 Web server 或写桌面程序才能展示，停止，改为 Markdown/静态线框；若必须展示数据库内部字段或私人正文，停止。
