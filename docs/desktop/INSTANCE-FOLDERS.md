# 实例文件夹：创建、连接、迁移和补全

## 日常操作

1. 打开 QUINTESSENCE，进入设置中的「实例文件夹」。
2. 点击「选择文件夹」，选择空文件夹或已有实例；也可以填写完整路径后点击「连接此文件夹」。
3. 软件自动识别、检查和准备实例，随后重新加载。没有自定义人格也可以直接聊天。
4. 在模型连接设置中配置授权凭据。凭据属于运行环境，可以保存在系统凭据管理器或由部署环境注入，不会写入实例数据。
5. 正常聊天，使用 Memory、Cognition 和会话历史。重新启动后继续使用同一实例。

切换期间不能提交新的业务操作；已有回答或模型后台任务仍运行时，应先等待它结束。取消文件夹选择不会切换实例。

## 文件夹里保存什么

- `instance.json`：稳定身份、组件路径、初始化状态、版本和恢复保证说明。
- `instance-host.json`：实例自己的宿主设置；不存放凭据。现有导入配置原文件保留。
- PCS 数据库：人格版本、会话、Cognition、来源关联、审核记录和投递状态。Cognition 不需要额外的空目录。
- Memory 数据库：Scope Recall 的实际持久数据和原有身份绑定。
- 删除账本、Anchor：必要的恢复安全资产，默认位于实例内。
- `persona/`：原有人格文件和完善说明；`persona-import/` 是人格管理界面实际使用的导入入口。
- `ui-preferences.json`：此实例的显示名、会话别名、归档等显示设置。
- `instance-history.jsonl`：登记、迁移和必要元数据补充的审计记录。

模型服务、通用运行依赖和凭据可以外置。它们不等同于实例的私人持久状态。完整安装产物包含现有 Scope Recall 运行依赖，不要求用户保留旧开发目录或安装 Python。

## 迁移完整实例

先关闭软件及其他实例写入进程，再复制整个文件夹。打开新的 QUINTESSENCE，选择复制后的文件夹即可。原身份和数据保留，旧绝对路径的记忆绑定和 Anchor 文件名会重绑定并记录审计。显示偏好的实例作用域使用稳定身份，移动路径后保持不变。

不要只复制数据库，也不要在软件写入期间直接复制其 SQLite 文件。不能把目录联接或符号链接当作迁移私人状态的方法。

## 部分实例

确认从未创建的组件可以补齐；已有文件不覆盖，已有 README 不修改。只有一个完整结构化人格文件时，新实例可将其作为初始人格导入：原文件不改写，新库使用实际的导入审核来源。多个候选版本而没有明确指定时停止自动选择。

已有 PCS 而 Memory 从未建立、已有 Memory 而 PCS 从未建立，均可按可验证的现有状态补全。没有旧组件状态记录时，缺少投递行不能证明组件从未建立；默认停止连接。只有用户核对并明确勾选“此前从未建立”、填写操作者和核对原因，才能登记一次组件声明。声明会写入实例及审计，属于用户确认，不是系统对历史完整性的证明。曾经建立后丢失、已有配置/投递见证或已登记 ready 的组件不能用此入口补空；不确定时必须找回原状态。初始化过程记录 pending、initializing、ready；曾开始初始化而文件后来不见，不会当作尚未初始化。

身份描述、实例配置、数据库、账本或 Anchor 缺失、损坏或不兼容时，软件停止连接并说明原因。不要通过删除其他标记来触发重新创建；这会破坏判断依据。

## 从没有安全记录的旧实例接入

默认连接不会擅自创建空账本来替代未知历史。只有明确选择「登记旧实例安全基线」、填写操作者与原因并确认限制后，才允许进行一次旧实例接入。

这个操作保留已有数据，记录 `pre_baseline_deletions=unprovable`，从当前状态开始启用后续删除和恢复保护。**它无法证明接入前发生过哪些删除，也不能保证旧备份中不存在后来删除的内容。** 若安全记录可能意外丢失，应先找回原记录。只缺部分安全资产时不能用此入口覆盖剩余见证；已登记实例不能重复接入。

## 恢复保护的真实边界

账本完整性、数据库水位、删除重放、存活见证检查和禁止不受保护删除等机制继续生效。数据库、账本和 Anchor 都位于一个文件夹时，整个文件夹共同回滚无法可靠检测。`deletion_safety=enforced` 表示当前账本与恢复检查在运行，不代表具备完整防共同回滚能力。

PCS 删除也不代表已经投递到 Memory 的正文会同步删除。使用旧备份或处理私人内容时，必须保留这个现有能力边界。

## 构建与开发验证

使用现有的 `build_sidecar.ps1` 和 `build_app.ps1`，将 LabRoot 指向独立实验目录。构建 Python 环境需安装 PyInstaller 6.16.0、Pillow 和经过验证的 Scope Recall 3.14.1 及其依赖。运行文件夹生命周期测试时也使用包含该依赖的 Python 环境，并使用现有离线测试入口，保持目录和网络隔离。

实例准备入口为 sidecar 的 `--prepare-instance <folder>`；默认拒绝不明状态。显式旧实例接入还需同时提供 `--adopt-legacy-by` 与 `--adopt-legacy-reason`。组件声明还需提供 `--declare-component-by`、`--declare-component-reason` 和 `--never-created-component memory`（或 `pcs`）；它与 PS06 安全基线登记分开，不能互相代替。这些是受信任的宿主操作，不是模型工具。

`QUINTESSENCE_DESKTOP_STATE_DIR` 可明确选择独立的宿主设置目录，适用于隔离验收；其中只保存模型设置和上次选择的实例位置。实例恢复不依赖它。实例文件夹不可用时，可在图形界面重新选择迁移后的文件夹。
